# 屏幕捕获功能测试指南

## 前置准备

### 1. 启动后端服务

```bash
cd desktop-ai-assistant/backend-service

# 方式1: 使用Docker (推荐)
docker-compose up -d

# 方式2: 本地运行
# 确保已安装Python 3.11+和依赖
pip install -r requirements.txt
python -m app.main
```

验证后端服务:
```bash
curl http://localhost:8000/health
# 应返回: {"status":"healthy"}
```

### 2. 配置API密钥

编辑 `backend-service/.env`:
```env
DEEPSEEK_API_KEY=your_deepseek_api_key_here
DEEPSEEK_API_BASE=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
```

### 3. 启动医生工作页面

```bash
cd medical-integration-system
pnpm install  # 首次运行
pnpm dev
```

访问: http://localhost:9527

### 4. 启动桌面AI助手

```bash
cd desktop-ai-assistant
npm install  # 首次运行
npm run dev
```

## 测试步骤

### 测试1: 基本功能测试

1. **打开医生工作页面**
   - 在浏览器中访问 http://localhost:9527
   - 切换到"临床医生"或"影像科医生"tab
   - 确保患者信息清晰显示

2. **打开桌面AI助手**
   - 启动桌面AI助手应用
   - 切换到"医疗系统"tab
   - 再切换到"智能识别"子tab

3. **执行屏幕捕获**
   - 点击"从屏幕获取患者信息"按钮
   - 观察截图过程和进度提示
   - 查看截图预览

4. **验证患者信息提取**
   - 检查提取的患者信息是否准确
   - 查看置信度评分
   - 如有错误,手动修正

5. **获取推荐**
   - 点击"确认并获取推荐"按钮
   - 等待AI生成推荐
   - 查看推荐的检查项目

6. **提交反馈**
   - 对推荐项目点击"采纳"或"不采纳"
   - 验证反馈是否成功提交

### 测试2: 边界情况测试

#### 测试2.1: 空白屏幕
- 截取空白或无患者信息的屏幕
- 预期: 提取失败或置信度很低

#### 测试2.2: 部分信息缺失
- 截取只包含部分患者信息的屏幕
- 预期: 提取部分字段,其他字段为空

#### 测试2.3: 低质量截图
- 缩小浏览器窗口后截图
- 预期: 置信度降低,可能需要手动修正

#### 测试2.4: 多个患者信息
- 截取包含多个患者的列表
- 预期: 提取第一个或最显著的患者信息

### 测试3: 错误处理测试

#### 测试3.1: 后端服务未启动
- 停止后端服务
- 尝试获取推荐
- 预期: 显示错误提示"API请求失败"

#### 测试3.2: API密钥无效
- 在.env中设置无效的API密钥
- 尝试提取患者信息
- 预期: 显示错误提示

#### 测试3.3: 网络超时
- 模拟网络延迟
- 预期: 显示超时错误

### 测试4: 性能测试

#### 测试4.1: 响应时间
- 记录从点击按钮到显示结果的时间
- 预期: 
  - 截图: < 2秒
  - OCR识别: < 3秒
  - 患者信息提取: < 5秒
  - 推荐生成: < 10秒

#### 测试4.2: 连续操作
- 连续执行5次完整流程
- 预期: 每次都能正常工作,无内存泄漏

## 常见问题

### Q1: 屏幕截图权限被拒绝
**A**: 在系统设置中授予屏幕录制权限
- macOS: 系统偏好设置 → 安全性与隐私 → 屏幕录制
- Windows: 设置 → 隐私 → 屏幕捕获

### Q2: OCR识别不准确
**A**: 
1. 确保截图清晰
2. 放大患者信息区域
3. 使用高分辨率显示器
4. 手动修正错误字段

### Q3: 推荐结果不合理
**A**:
1. 检查患者信息是否准确
2. 补充更详细的主诉和病史
3. 通过反馈功能报告问题

### Q4: API调用失败
**A**:
1. 检查后端服务状态: `curl http://localhost:8000/health`
2. 检查API密钥配置
3. 查看后端日志: `docker-compose logs -f api`
