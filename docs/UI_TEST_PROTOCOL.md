## 测试场景定义

### 场景1: Deepseek Provider测试

**目标**: 验证选择deepseek提供商后,前端能否正常对话

**测试步骤**:

1. **访问前端页面**
   - 操作: 在浏览器地址栏输入 `http://localhost:5928`
   - 预期结果: 页面正常加载,显示AI助手界面
   - 记录: Console是否有错误? Network是否有失败请求?

2. **进入设置页面**
   - 操作: 点击左侧导航栏的"设置"按钮
   - 预期结果: 右侧显示设置面板
   - 记录: Console是否有错误? Network是否有失败请求?

3. **进入AI模型设置**
   - 操作: 点击设置面板中的"AI 模型"标签
   - 预期结果: 显示AI模型配置界面
   - 记录: Console是否有错误? Network是否有失败请求?

4. **配置调用路由**
   - 操作: 在"调用路由"下拉框中选择"后端服务（由后端模型配置决定）"
   - 预期结果: 下拉框显示选中状态
   - 记录: 配置是否保存? UI是否有变化?

5. **选择Deepseek提供商**
   - 操作: 在"后端提供商"下拉框中选择"deepseek"
   - 预期结果: 下拉框显示"deepseek"
   - 记录: 是否触发了API请求? 是否有错误?

6. **保存配置**
   - 操作: 点击"保存设置"按钮
   - 预期结果: 显示"设置已保存"提示
   - 记录: Network中是否有保存配置的请求? 是否成功?

7. **测试对话连接**
   - 操作: 点击"测试对话连接"按钮
   - 预期结果: 显示"测试成功"或具体的AI回复
   - 记录: 
     * Console中的完整错误信息
     * Network中的请求URL、Method、Status
     * Request Headers
     * Request Payload
     * Response Headers
     * Response Body
     * 后端日志中的对应记录

8. **进入AI对话页面**
   - 操作: 点击左侧导航栏的"AI对话"按钮
   - 预期结果: 显示对话界面,顶部显示当前配置(路由:后端,提供商:deepseek)
   - 记录: 配置信息是否正确显示?

9. **发送测试消息**
   - 操作: 在输入框输入"你好",点击发送或按Enter
   - 预期结果: 
     * 消息显示在对话区域
     * 显示"正在输入..."或加载动画
     * 收到AI回复
   - 记录:
     * 消息是否发送成功?
     * Console中的错误信息
     * Network中的请求详情
     * 是否收到回复?
     * 回复内容是什么?
     * 后端日志中的处理记录

10. **验证回复内容**
    - 操作: 检查AI回复的内容
    - 预期结果: 回复内容合理,符合deepseek模型的特征
    - 记录: 回复质量如何? 是否有异常?

## 测试执行规则

### 必须遵守的规则

1. **顺序执行**: 必须按照场景1 → 场景2 → 场景3的顺序执行
2. **完整记录**: 每个步骤都必须记录实际结果,不能跳过
3. **错误记录**: 发现错误时,必须完整记录所有信息(Console、Network、后端日志)
4. **不提前修复**: 在完成所有场景测试前,不得开始修复任何问题
5. **问题汇总**: 完成所有测试后,必须汇总所有问题并排序
6. **逐个修复**: 每次只修复一个问题
7. **修复后验证**: 每修复一个问题,必须重新运行完整测试流程
8. **保持追踪**: 使用问题清单追踪所有问题的状态

### 禁止的行为

- ❌ 跳过任何测试步骤
- ❌ 看到错误就立即修复
- ❌ 同时修复多个问题
- ❌ 不记录错误详情
- ❌ 不验证修复效果
- ❌ 假设问题已解决
