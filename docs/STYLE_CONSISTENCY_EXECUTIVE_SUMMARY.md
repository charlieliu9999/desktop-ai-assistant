## 🔍 主要问题

### 1. CSS变量重复定义 (🔴 严重)

**问题**: `index.css` 和 `App.css` 中定义了相同的 CSS 变量，但值不一致。

**影响**:
- 主色调冲突: `#646cff` vs `#007AFF`
- 组件样式不可预测
- 后加载的 CSS 会覆盖前面的定义

**解决方案**: 删除 `App.css` 中的变量定义，统一使用 `index.css`

**工时**: 2小时  
**风险**: 中 (需要全面测试)

---

### 2. 样式实现方式混乱 (🔴 严重)

**问题**: 项目中同时使用了 5 种不同的样式方法，没有明确的使用规范。

**发现的方法**:
1. Tailwind CSS 工具类 (主流)
2. 内联样式
3. CSS 变量
4. 全局 CSS 类
5. 动态类名组合

**影响**:
- 代码审查困难
- 新开发者学习成本高
- 难以维护和重构
- 样式优先级冲突

**解决方案**: 建立明确的样式使用优先级规范

**工时**: 4小时 (编写文档)

---

### 3. 玻璃效果应用不一致 (🟡 中等)

**问题**: 虽然已有规范文档，但部分组件未遵守。

**具体问题**:
- 使用了废弃的 `dark:glass-dark` 类 (6处)
- 玻璃效果条件判断逻辑分散
- 未统一使用 CSS 变量

**影响**:
- 视觉不一致
- 用户配置不生效
- 代码冗余

**解决方案**: 
1. 移除废弃类 (30分钟)
2. 创建统一的 Hook (2小时)
3. 更新所有组件 (8小时)

**工时**: 10.5小时

---

### 4. 深色模式处理不统一 (🟡 中等)

**问题**: 三种深色模式实现方式并存。

**方式**:
1. CSS 媒体查询 `@media (prefers-color-scheme: dark)`
2. CSS 类选择器 `.dark`
3. Tailwind `dark:` 前缀

**影响**:
- 可能产生冲突
- 主题切换不可预测
- 难以调试

**解决方案**: 统一使用 `.dark` 类 + Tailwind `dark:` 前缀

**工时**: 8小时

## 🚨 风险评估

### 高风险项

**删除 CSS 变量定义**
- **风险**: 可能破坏依赖它的组件
- **缓解**: 先全局搜索，再渐进式迁移
- **回滚计划**: 保留备份文件

### 中风险项

**统一组件样式**
- **风险**: 可能改变现有视觉效果
- **缓解**: 截图对比，充分测试
- **回滚计划**: Git 分支管理

### 低风险项

**创建文档和 Hook**
- **风险**: 几乎无风险
- **说明**: 不修改现有代码，只新增
